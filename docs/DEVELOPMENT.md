# 开发接续说明

## 当前可用成果

主工程是 `demo/`，采用无构建步骤的原生 HTML、CSS、JavaScript，三端共享业务模型。小程序目前是手机尺寸的 Web 演示，不是微信原生小程序工程。服务端仅有本机静态资源服务，没有生产业务 API、真实设备网关或本地数据库。

当前界面已覆盖扫码、手机入库、合同与续租、客户与第一所有人、逐用户授权、设备操作与回执、到期停机、提醒、收入统计、备份恢复、海南地图逐级展开、区域设备和运行详情。

## 模块入口

- `demo/dist/demo.js`：领域模型、虚构样例、演示时间、租赁、权限、指令回执、同步镜像、加密备份。
- `demo/dist/app.js`：三端切换、路由、共享弹窗、扫码和演示控制台。
- `admin.js` / `mini.js`：后台与手机端业务流程。
- `monitor.js` / `monitor-pages.js` / `monitor-map.js`：监控总览、区域列表、详情、报警与地图下钻。
- `map-data.js` / `map-levels.js`：内置地图数据；`demo/qa/build-map-levels.py` 可重建下钻几何。
- `demo/API.md`：后续服务拆分的接口草案。

修改 `demo/dist/` 即可重新加载界面。`prototype/` 保留用于追溯需求，不应把旧模型直接替换到当前 Demo。

## 已确认的业务规则

1. 设备通过 4G 模块和自有云服务器通信；二维码为厂商代号 + 变频器型号 + 4G 模块 ID。
2. 用户身份以微信绑定手机号为准；扫码先获得查看关系，启停、调频、复位由管理员分别授予。
3. 同一设备可关联多用户；第一所有人为签订合同且由管理员登记付款的用户，不能由扫码先后决定。
4. 按月出租，提前 7 / 3 / 1 天提醒；未续租到期停机，续租不自动启动。离线不能当作停机成功，正式方案必须落实终端到期策略与补发回执。
5. 姓名、电话、登记时间、设备关系、合同到期、权限等用户主数据以本地电脑为准，云端和小程序跟随同步；电机遥测、告警、控制回执留在云端。
6. 备份支持保存到本地/U 盘，光盘由操作系统刻录。恢复前需校验、比对、可先备份当前数据；不会用用户备份回滚云端遥测或收款流水。
7. 短信充值、余额、按条扣费、供应商发送只预留契约，价格、支付方式、扣费失败处理尚待确认。
8. 地图省→市县→可用区级数据逐级展开；设备只有明确匹配市县的 districtCode 才计入区级，不能根据地址文本猜测。

## 下一阶段开发顺序

| 阶段 | 要形成的可验收结果 |
| --- | --- |
| 领域与接口定稿 | 数据字典、用户/设备身份约束、合同与收款账本、权限矩阵、接口版本和幂等规则 |
| 本地用户主数据服务 | 本地数据库、管理员身份、加密备份/恢复、审计与云同步队列、版本冲突规则 |
| 云端与 4G 接入 | 设备认证、协议/寄存器映射、遥测和告警、指令 ID、超时重试、回执、到期停机固件联调 |
| 三端正式化 | 微信登录和手机号、原生扫码，后台真实接口，监控订阅和数据新鲜度，保持现有统一 UI |
| 联调与上线 | 多用户越权测试、断网/补传/重复回执、续租与到期竞态、备份恢复演练、部署监控和发布回滚 |

`reference/simplied-iot-monitoring-go-main` 仅供 Go / Kafka / WebSocket 等架构研究，未完成与本租赁模型的对接或生产安全验收。应先明确是否采用，再做独立依赖与许可证核查。
